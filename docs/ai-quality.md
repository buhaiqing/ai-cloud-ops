# AI 诊断质量标准 (T13)

> **这是 P1 任务。** P4（AI 增强 > 传统规则）是核心赌注，没有衡量标准这个赌注没法验证。M1 第一周必须先定这个，再开始 coding。

## 为什么需要这个文档

P4（设计文档 Premises）："AI 提供的'根因诊断 + 修复建议'价值大于传统阈值告警。"

但"AI 增强"是什么？常见回答：
- ❌ "3 秒内给个看起来合理的建议"——LLM 几乎都能做到，没有差异化
- ❌ "覆盖率 100% 的告警都能分析"——但准确率呢？
- ✅ **"根因准确率 ≥ X%、修复建议可执行率 ≥ Y%、零幻觉率 ≥ Z%"**——可衡量、可 CI 验证

没有这个标准：
- AI 改了一行 prompt 不知道变好还是变坏
- 升级版本不知道退化没
- 6 个月后回头看 P4 没法判断是赢是输
- OSS 用户问"AI 变笨了吗"答不上来

## 衡量维度（5 维评分卡，每维 1-5 分）

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| **根因准确性** | 幻觉 / 错误 | 部分正确（提到正确方向但具体错了） | 准确指向真实根因 |
| **修复建议可执行性** | 通用文本（"请检查实例"） | 结构化但缺少参数 | 结构化 + 具体命令/参数 + 预期结果 |
| **证据链完整性** | 无引用 | 引用了相关 metric | 引用 + 关联到具体时间窗 + 关联资源 |
| **幻觉率** | 频繁幻觉资源名/账号 ID | 偶发幻觉 | 零幻觉（不存在的资源不被提到） |
| **响应时间** | > 30s | 5-15s | < 5s（用户在线等待） |

**Pass 阈值（每个 alert）：** 总分 ≥ 18/25（72%）。任何一维 ≤ 2 分算 fail。

## 基线样本（10 个，详见 `tests/eval/baseline_samples.json`）

| # | 类型 | 难度 | 期望根因关键词 | 期望建议类型 |
|---|---|---|---|---|
| 1 | ECS CPU 高 | 易 | "CPU 持续 > 90%" | 重启或扩容 |
| 2 | RDS 连接数爆 | 易 | "max_connections 满" | kill long query 或扩容 |
| 3 | SLB 5xx 突增 | 中 | "后端 ECS 健康检查失败" | 检查 backend health |
| 4 | ECS 宕机 | 中 | "实例状态 Stopped" | 启动实例或迁移 |
| 5 | 磁盘满 | 易 | "磁盘使用率 > 95%" | 清理日志或扩容 |
| 6 | 网络丢包 | 难 | "VPC 路由表变更 / 安全组误改" | 检查最近变更 |
| 7 | 数据库慢查询 | 中 | "全表扫描 / 索引缺失" | 添加索引 / kill query |
| 8 | OSS 403 | 中 | "RAM 策略变更 / 凭证过期" | 检查权限 |
| 9 | 多 ECS 同步告警 | 难 | "共享依赖 (RDS/NAS) 故障" | 检查共享依赖 |
| 10 | 误报（noop） | 易 | "无明确根因" | 抑制 / 静默 |

## LLM-as-Judge 评分实现

`tests/eval/judge.py` 使用 Claude 给样本评分：

```python
# 每个 alert 样本 → 5 维评分卡 → 总分
# CI gate: 平均总分 ≥ 18/25 且任何一维 ≤ 2 分的样本数 ≤ 1
```

**CI gate 行为**：
- 平均 ≥ 18 → pass
- 17 ≤ 平均 < 18 → warn（允许合并但要发 issue）
- 平均 < 17 → fail，阻塞合并

## 落地时间线（M1）

- **Week 1 (Day 1-2)**：本文件定稿 + `tests/eval/baseline_samples.json` 完整
- **Week 2 (Day 3-4)**：实现 `tests/eval/judge.py` + 跑基线得到 baseline score
- **Week 3 (Day 8-10)**：AI Agent 实现完成后，第一次跑 eval，验证 ≥ 18
- **Week 4 (Day 11-14)**：打磨 + 录制 demo 时展示 eval 分数作为卖点

## 杀掉这个项目（P4 失败）的信号

如果 3 个月后：
- 平均 eval 分数 < 16
- 幻觉率仍 > 5%
- 用户反馈"AI 建议没用"

→ kill criterion 触发，停止投入。

详见 `design.md` 待定义的 T18（kill criterion + data retention policy）。
